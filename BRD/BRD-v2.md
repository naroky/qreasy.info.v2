## 1. ความเป็นมา

QREASY.INFO V1 เป็นเว็บไซต์สร้าง QR Code จาก URL แบบง่าย ผู้ใช้กรอก URL ผ่าน Google reCAPTCHA แล้วส่งคำขอไปให้เซิร์ฟเวอร์สร้างภาพ QR Code รายได้มาจาก Google AdSense และวัดผลการใช้งานด้วย Google Analytics

ข้อจำกัดของ V1 ที่พบ

- รองรับเฉพาะ URL
- ปรับแต่ง QR Code ไม่ได้ (สี ขนาด โลโก้ รูปแบบไฟล์)
- ต้องผ่าน reCAPTCHA ทุกครั้ง ทำให้ใช้งานช้าลง
- ไม่มีระบบสมาชิก ผู้ใช้จึงเก็บหรือเรียกดู QR Code ที่เคยสร้างไม่ได้ และเว็บไซต์ไม่มีฐานผู้ใช้ของตัวเอง
- ไม่มีหน้าจัดการระบบสำหรับผู้ดูแล การเปลี่ยนโฆษณาหรือการตั้งค่า Analytics ต้องแก้โค้ดโดยตรง
- ไม่มีหน้าข้อมูลเว็บไซต์ (About, Contact, Privacy Policy)
- ไม่มี robots.txt และ sitemap.xml จึงเสียโอกาสด้าน SEO

### 2.1 กลยุทธ์รายได้

**รูปแบบธุรกิจของ V2: บริการฟรี 100% รายได้มาจากพื้นที่โฆษณา** ผู้ใช้ทุกคน (Guest และ Member) ใช้ทุกฟีเจอร์ได้โดยไม่เสียเงิน

ผู้ใช้เว็บสร้าง QR Code มักอยู่ในเว็บไม่นาน (ประมาณ 30–60 วินาที) และเปิดไม่กี่หน้า รายได้จากโฆษณาต่อผู้ใช้จึงต่ำ จึงต้องใช้พื้นที่โฆษณาหลายรูปแบบและวัดผลเพื่อปรับปรุงต่อเนื่อง ลำดับมีดังนี้

| ลำดับ | แหล่งรายได้ | Phase |
| --- | --- | --- |
| 1 | โฆษณา Display (Google AdSense) วางในจุดที่ผู้ใช้สนใจหน้าจอ เช่น ข้างพรีวิว QR และ sticky anchor บนมือถือ | 1 |
| 2 | Affiliate สินค้าที่ผู้ใช้ต้องใช้ต่อหลังได้ QR Code เช่น ป้ายอะคริลิก สติกเกอร์ งานพิมพ์ นามบัตร NFC (Shopee, Lazada, Involve Asia, ACCESSTRADE) | 1 |
| 3 | บทความและ FAQ เพื่อเพิ่ม traffic จาก SEO และจำนวนหน้าที่ผู้ใช้เปิด | 1 |
| 4 | ทดสอบเครือข่ายโฆษณาอื่น (Ezoic หรือ Google Ad Manager ผ่านพาร์ตเนอร์ MCM) แบบ A/B เทียบกับ AdSense | 1.1 |
| 5 | Direct sponsorship: ขายพื้นที่แบนเนอร์ให้ร้านพิมพ์หรือร้านป้ายโดยตรง | 1.1 |
| ~~6~~ | ~~แพ็กเกจ Pro แบบรายเดือนหรือรายปี~~ | **พักไว้** (ดูหัวข้อ 6.12) |

หลักการ: ฟีเจอร์ทั้งหมดใน V2 ฟรี ถ้าในอนาคตกลับมาทำแพ็กเกจเสียเงิน จะเพิ่มเฉพาะความสามารถใหม่ ไม่ย้ายฟีเจอร์ที่เคยฟรีไปเป็นของเสียเงิน

## 3. ขอบเขต

### 3.1 อยู่ในขอบเขต V2 (Phase 1)

- สร้าง Static QR Code หลายประเภท พร้อมพรีวิวทันที
- ปรับแต่งรูปลักษณ์ QR Code และดาวน์โหลดได้หลายรูปแบบไฟล์
- ระบบสมาชิก: สมัครสมาชิก, Login/Logout, ลืมรหัสผ่าน, จัดการโปรไฟล์ และบันทึกประวัติ QR Code
- หน้า CMS สำหรับผู้ดูแล: จัดการผู้ใช้ จัดการตำแหน่งโฆษณา ตั้งค่า Google Analytics และดู Dashboard
- โฆษณา Google AdSense และ Google Analytics 4 รวมถึงการวัดผลส่วนของสมาชิก
- Affiliate: แสดงสินค้าแนะนำตามประเภท QR และให้ Admin จัดการรายการสินค้าใน CMS
- รองรับหลายเครือข่ายโฆษณาและการทดสอบ A/B (Phase 1.1)
- พื้นที่แบนเนอร์ผู้สนับสนุน (Direct sponsorship) (Phase 1.1)
- หน้าเว็บรองรับมือถือ และมีภาษาไทยกับภาษาอังกฤษ
- หน้า About, Contact, Privacy Policy, Terms of Use และ FAQ
- ระบบขอความยินยอมใช้คุกกี้ (Cookie Consent)
- พื้นฐาน SEO

### 3.2 พักไว้ — แพ็กเกจ Pro (ยังไม่ทำใน V2)

ตามการตัดสินใจวันที่ 19 ต.ค. 2026 ให้ V2 เป็นบริการฟรีก่อน รายการต่อไปนี้จึงพักไว้ จะทบทวนอีกครั้งเมื่อมีข้อมูล traffic และรายได้จากโฆษณาของ V2 แล้ว ข้อกำหนดเดิมยังเก็บไว้ในหัวข้อ 6.12 เพื่อใช้อ้างอิง

- Dynamic QR Code และสถิติการสแกน
- แพ็กเกจ Free/Pro และระบบชำระเงิน (บัตรเครดิต, PromptPay)
- สิทธิ์ไม่เห็นโฆษณาแบบเสียเงิน
- Bulk generation และไฟล์ PDF พร้อมพิมพ์
- การจัดการแพ็กเกจ ราคา และคูปองใน CMS

### 3.3 อยู่นอกขอบเขต V2 (พิจารณาภายหลัง)

- Public API สำหรับนักพัฒนา
- การจัดการเนื้อหาหน้าเว็บ (About, FAQ, บทความ) ผ่าน CMS
- แพ็กเกจสำหรับทีมหรือองค์กร (หลายผู้ใช้ในบัญชีเดียว)

## 5. กลุ่มผู้ใช้และบทบาทในระบบ

### 5.1 กลุ่มผู้ใช้เป้าหมาย

- **ผู้ใช้ทั่วไปบนมือถือ:** อยากได้ QR Code ของลิงก์หรือข้อความแบบเร่งด่วน
- **ร้านค้าและธุรกิจรายย่อย:** ต้องการ QR Code สำหรับเมนู Wi-Fi โซเชียลมีเดีย หรือนามบัตร และสร้างซ้ำบ่อย
- **ครูและนักเรียน:** ใช้ QR Code ประกอบเอกสารหรือสื่อการสอน
- **นักออกแบบ:** ต้องการไฟล์เวกเตอร์ (SVG) ความละเอียดสูงไว้ใช้กับงานพิมพ์

### 5.2 บทบาทในระบบ (Roles)

| บทบาท | สิทธิ์หลัก |
| --- | --- |
| Guest | สร้าง ปรับแต่ง และดาวน์โหลด QR Code โดยไม่ต้อง Login |
| Member | ทุกอย่างที่ Guest ทำได้ บวกกับบันทึก QR Code, บันทึก preset รูปแบบ และจัดการบัญชีของตัวเอง |
| Admin | เข้าหน้า CMS: จัดการผู้ใช้ทั่วไป ดู Dashboard และจัดการโฆษณาและ GA |
| Super Admin | ทุกอย่างที่ Admin ทำได้ บวกกับแต่งตั้งหรือถอดถอน Admin และดู Audit Log ทั้งหมด |

## 8. ตัวชี้วัดความสำเร็จ (KPI)

ค่าเป้าหมายจะกำหนดหลังได้ค่าฐานจาก Analytics ของ V1 (ดู Q-03)

| KPI | วิธีวัด |
| --- | --- |
| จำนวน QR Code ที่ดาวน์โหลดต่อเดือน | GA event `qr_download` |
| อัตราการดาวน์โหลดหลังเปิดหน้า (Conversion) | จำนวน `qr_download` ÷ จำนวน page view |
| จำนวนสมาชิกใหม่ต่อเดือน | GA event `sign_up` และข้อมูลในฐานข้อมูล |
| อัตราการสมัครสมาชิก (Sign-up rate) | จำนวน `sign_up` ÷ จำนวนผู้ใช้ไม่ซ้ำ |
| สมาชิกที่กลับมาใช้งานใน 30 วัน (Retention) | Dashboard CMS / GA |
| Organic traffic | Google Search Console / GA |
| รายได้โฆษณาต่อ 1,000 page view (RPM) แยกตามเครือข่ายและกลุ่ม A/B | รายงานของเครือข่ายโฆษณา + GA |
| CTR ของ Affiliate และรายได้ค่าคอมมิชชันต่อเดือน | CMS (คลิก) + รายงานของแพลตฟอร์ม Affiliate |
| รายได้รวมต่อผู้ใช้ 1,000 คน (Display ads + Affiliate + แบนเนอร์ผู้สนับสนุน) | รวมจากทุกแหล่ง |
| อัตราการเห็นโฆษณา (Viewability) และสัดส่วนผู้ใช้ที่ใช้ ad blocker | รายงานของเครือข่ายโฆษณา + GA |
| คะแนน Core Web Vitals | Search Console / PageSpeed Insights |

## 9. สมมติฐาน

- A-01: QR Code ใน Phase 1 เป็นแบบ Static ทั้งหมด จึงสร้างได้บนเบราว์เซอร์ของผู้ใช้ ส่วนเซิร์ฟเวอร์ใช้สำหรับระบบสมาชิก การบันทึก QR และ CMS เท่านั้น
- A-02: เมื่อสร้าง QR Code บนเบราว์เซอร์แล้ว ไม่จำเป็นต้องใช้ CAPTCHA ในขั้นตอนสร้าง แต่ยังใช้ในหน้าสมัครสมาชิก Login และ Contact
- A-03: ใช้ Google AdSense และ Google Analytics 4 ต่อจาก V1
- A-04: ผู้ใช้หลักเป็นคนไทย และใช้งานผ่านมือถือเป็นส่วนใหญ่ จึงเลือก Login ด้วย Google และ LINE
- A-05: ทุกฟีเจอร์ใน V2 ฟรี การสมัครสมาชิกไม่มีค่าใช้จ่าย และการสร้าง QR Code ไม่บังคับให้ Login
- A-06: Phase 1 มีผู้ดูแลระบบจำนวนน้อย (ไม่เกิน 5 คน)
- A-07: ผู้ใช้หลักอยู่ในไทย จึงเลือกแพลตฟอร์ม Affiliate และ payment gateway ที่ทำงานในไทย
- A-08: เจ้าของผลิตภัณฑ์สมัครโปรแกรม Affiliate และบัญชีเครือข่ายโฆษณาได้ในนามบุคคลหรือนิติบุคคลของเว็บไซต์

## 10. ข้อจำกัดและความเสี่ยง

| รหัส | ความเสี่ยง | แนวทางรับมือ |
| --- | --- | --- |
| R-01 | ยังไม่รู้พฤติกรรมหน้าผลลัพธ์ของ V1 อาจมีผู้ใช้ที่พึ่งพาพฤติกรรมเดิมอยู่ | ทดสอบ V1 จริงหรือสอบถามเจ้าของผลิตภัณฑ์ก่อนปิด V1 |
| R-02 | การเปลี่ยนโครงสร้างเว็บอาจทำให้อันดับ SEO ลดลง | ตั้ง redirect 301 และส่ง sitemap ใหม่ |
| R-03 | โลโก้หรือสีที่ผู้ใช้เลือกอาจทำให้ QR Code สแกนไม่ได้ | บังคับ Error Correction ระดับ H เมื่อมีโลโก้ และเตือนเรื่อง contrast |
| R-04 | QR Code อาจถูกใช้เพื่อหลอกลวง (Phishing) | ตรวจ scheme ของ URL และพิจารณาใช้บริการตรวจลิงก์อันตรายใน Phase ถัดไป |
| R-05 | Cookie consent อาจทำให้ข้อมูล GA และรายได้โฆษณาลดลง | ใช้ Google Consent Mode เพื่อลดผลกระทบ |
| R-06 | การเก็บข้อมูลสมาชิกเพิ่มความรับผิดชอบด้าน PDPA และความเสี่ยงที่ข้อมูลรั่วไหล | เก็บข้อมูลเท่าที่จำเป็น เข้ารหัสข้อมูล ใช้ 2FA กับ Admin มี Audit Log และแผนรับมือเหตุข้อมูลรั่ว |
| R-07 | QR Code ที่สมาชิกบันทึกอาจมีข้อมูลอ่อนไหว เช่น รหัสผ่าน Wi-Fi | เตือนผู้ใช้ก่อนบันทึก และให้เลือกไม่บันทึกรหัสผ่าน Wi-Fi |
| R-08 | การมีระบบสมาชิกและ backend ทำให้ค่า hosting และงานดูแลระบบเพิ่มขึ้นจากเว็บ static | เลือกบริการ managed (database, email) และเริ่มด้วยแพ็กเกจขนาดเล็ก |
| R-09 | ตั้งค่าโฆษณาผิดใน CMS อาจทำให้รายได้หายหรือผิดนโยบาย AdSense | จำกัดสิทธิ์เฉพาะ Admin บันทึก Audit Log และตรวจรูปแบบ ID ก่อนบันทึก |
| R-10 | วางโฆษณาใกล้ปุ่มดาวน์โหลดเกินไป ทำให้ผู้ใช้คลิกโดยไม่ตั้งใจ จนบัญชี AdSense โดนระงับ | กำหนดระยะห่างขั้นต่ำใน TRD และตรวจทุกตำแหน่งก่อนเปิดใช้ |
| R-11 | สคริปต์ของเครือข่ายโฆษณาบางราย (เช่น Ezoic) ทำให้เว็บช้าลงและเสีย SEO | ทดสอบแบบ A/B กับ traffic บางส่วนก่อน และวัด Core Web Vitals คู่กับ RPM |
| R-12 | ไม่เปิดเผยว่าเป็นลิงก์ Affiliate อาจผิดเงื่อนไขของแพลตฟอร์มและเสียความเชื่อใจของผู้ใช้ | ติดป้ายทุกการ์ด (BR-102) |
| R-13 | รายได้ขึ้นกับโฆษณาเพียงอย่างเดียว ถ้าบัญชี AdSense ถูกระงับหรือ RPM ลดลง รายได้จะหายทันที | มีเครือข่ายสำรอง (BR-111), Affiliate และแบนเนอร์ผู้สนับสนุนที่ไม่ขึ้นกับ Google และตรวจนโยบายโฆษณาก่อนเปิดตำแหน่งใหม่ทุกครั้ง |
| R-14 | ผู้ใช้ที่ใช้ ad blocker ไม่สร้างรายได้ | ใช้ Affiliate และแบนเนอร์ผู้สนับสนุนแบบเสิร์ฟจากโดเมนตัวเอง (first-party) ซึ่งถูกบล็อกน้อยกว่า และติดตามสัดส่วน ad blocker เป็น KPI |
| R-15 | ค่าใช้จ่ายของระบบสมาชิกและ backend อาจสูงกว่ารายได้โฆษณาในช่วงแรก | เริ่มด้วยแพ็กเกจ hosting และ database ขนาดเล็กหรือฟรี แล้วติดตามต้นทุนเทียบกับรายได้รายเดือน |
